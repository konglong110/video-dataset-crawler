# docs/ — 项目管理与设计文档

本目录是**架构师窗口**的产出，也是**开发窗口的上下文来源**。协作模型：
架构师在这里写设计/工单并推送 → 开发窗口读 repo + 一段短提示词即可执行 → 交回 diff → 架构师验收并更新看板。

| 文件 | 作用 | 谁读 |
|---|---|---|
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | 框架设计：分层、数据流、数据模型、数据集分类、扩展点 | 所有窗口，动手前 |
| [`DEV_GUIDE.md`](DEV_GUIDE.md) | 开发规约：四条铁律、crawl.py 骨架、命令约定、通用验收 | 每个开发窗口必读 |
| [`TASK_BOARD.md`](TASK_BOARD.md) | 任务看板：状态/优先级/依赖，项目进度唯一权威来源 | 架构师维护，开发窗口查自己的任务 |
| [`tasks/T0x-*.md`](tasks/) | 单个需求的实现工单（需求实现文档），含设计决策 + 验收标准 | 被指派该任务的开发窗口 |

## 派单方式（架构师 → 开发窗口）

新开一个开发窗口，粘贴短提示词，指向对应工单即可。模板：

```
你是资深 Python 爬虫工程师，执行一张已设计好的开发工单，只做被指派的任务，不扩大范围。
先读 repo 建立上下文（必读）：docs/DEV_GUIDE.md、docs/ARCHITECTURE.md、docs/tasks/<工单号>.md，
以及工单里点名的 common/ 和 datasets/ 文件。
任务：<工单号 + 一句话目标>
约束：遵守 DEV_GUIDE；只动工单允许的文件；风格与现有代码一致；不创建 PR 除非我要求。
验收：按工单"验收标准"逐条自查通过再提交。
交付：提交到本窗口指派的开发分支；回报 ①改了哪些文件 ②如何自测 ③遗留问题/需架构师决策的点。
```
